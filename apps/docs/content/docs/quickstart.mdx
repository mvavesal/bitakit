Build a small Next.js application with BitaKit already connected.
You need **Node.js 24**, **npm 10 or newer**, and an internet connection.

<Callout title="Ready to build">
  The generator installs BitaKit from npm and connects the pieces for you. No repository checkout or
  manual package build is needed.
</Callout>

## 1. Create your app

```sh
npx @bitakit/create-app my-app --framework next --features none --yes
```

This creates a minimal Next.js app in `my-app`, the shortest path to a first feature.
Choose a new directory name: the generator does not overwrite an existing project.

To pick a framework and extras interactively — an application shell with settings pages,
⌘K quick search, a sample Todos plugin — run `npx @bitakit/create-app my-app` instead. The
generator adds the dependencies each choice needs.

## 2. Start developing

```sh
cd my-app
npm run dev
```

Open the address printed in your terminal (usually http://localhost:3000). You see
**Welcome**. Edit `src/app/page.tsx` and the page updates. The generator has already
connected BitaKit to your application's router: `next.config.ts` runs discovery with
`withBitaKit`, and the root layout renders `<BitaKitProvider>` from the generated
`src/bitakit.gen.tsx`. You did not write any setup code.

## 3. Add a feature

```sh
npx bitakit add plugin notes
```

This creates `src/plugins/notes/` with a service, typed events, actions, a navigation link
and a page at `/notes`. The dev server picks it up; there is no registry to edit. Open
`src/plugins/notes/ui/pages/index.tsx` to see how a page binds actions with `<Action>` and
reads the service with `useServiceState`. Check the project at any time with
`npx bitakit doctor`.

## 4. Make it yours

Edit your app's native routes and components. Keep product behavior in your application;
use BitaKit packages for shared capabilities.

| You own                  | BitaKit connects                                      |
| ------------------------ | ----------------------------------------------------- |
| Pages and business logic | Runtime and plugin lifecycle                          |
| Framework routes         | Links and navigation through the selected integration |
| Product configuration    | Installed capabilities and their dependencies         |

You can use your framework's router directly in application code. BitaKit does not
replace it, and plugins do not need their own router setup on every page.

## Choose your starting point

To create a new project with an application shell and quick search:

```sh
npx @bitakit/create-app my-app --framework next --features shell,quick-search
```

Shell includes App Preferences as a prerequisite. Your home page then lives in a route
group: `src/app/(app)/page.tsx`. Authentication, a database and email are separate
integrations; the generator does not create a backend.

### Framework support

Next.js projects run with the default bundler; discovery writes real files, so Turbopack
and Webpack behave the same. TanStack Start is available as an experimental generator
option; broader compatibility is still being verified.
