Build a small To-do feature with a service, actions and events. This example runs in Node.js with `@bitakit/core` and no framework.

It uses manual composition: `definePlugin` groups the files, and the record keys supply the same IDs discovery derives from file paths in an app. For the discovery-based workflow, start with [Plugins and lifecycle](/docs/concepts/plugins).

Install `@bitakit/core`, then create the following files in your project. Keep their relative paths. No React, router, database or file discovery is required. The same files ship in the package under `examples/`.

The service owns tasks in a store, three actions invoke it, the events file declares `todos.changed`, and the plugin groups them. The delete action is disabled while the list is empty because its `enabled` function reads the store.

## todos/services/tasks.mjs

```js
import { defineService } from '@bitakit/core';

/** The Todos data and behavior: an observable store plus the methods that change it. */
export default defineService(({ store, events }) => {
  const state = store({ items: [], nextId: 1 });

  return {
    state,
    create(title) {
      const task = { id: state.get().nextId, title, done: false };
      state.set((s) => ({ items: [...s.items, task], nextId: s.nextId + 1 }));
      events.emit('todos.changed', { kind: 'added', id: task.id });
      return task;
    },
    list: () => [...state.get().items],
    delete(id) {
      const before = state.get().items.length;
      state.set((s) => ({ ...s, items: s.items.filter((task) => task.id !== id) }));
      const removed = state.get().items.length < before;
      if (removed) events.emit('todos.changed', { kind: 'removed', id });
      return removed;
    },
  };
});
```

## todos/events.mjs

```js
import { defineEvents, event } from '@bitakit/core';

export default defineEvents({
  changed: event(),
});
```

## todos/actions/create.mjs

```js
import { defineAction } from '@bitakit/core';

export default defineAction({
  execute: ({ services, input }) => services.todos.tasks.create(input),
});
```

## todos/actions/list.mjs

```js
import { defineAction } from '@bitakit/core';

export default defineAction({
  execute: ({ services }) => services.todos.tasks.list(),
});
```

## todos/actions/delete.mjs

```js
import { defineAction } from '@bitakit/core';

export default defineAction({
  // Re-evaluated whenever the tasks store changes: disabled while the list is empty.
  enabled: ({ services }) => services.todos.tasks.state.get().items.length > 0,
  execute: ({ services, input }) => services.todos.tasks.delete(input),
});
```

## todos/plugin.mjs

```js
import { definePlugin } from '@bitakit/core';
import tasks from './services/tasks.mjs';
import events from './events.mjs';
import create from './actions/create.mjs';
import list from './actions/list.mjs';
import remove from './actions/delete.mjs';

export default definePlugin({
  id: 'todos',
  events,
  services: { tasks }, // todos.tasks → services.todos.tasks
  actions: { create, list, delete: remove }, // todos.create, todos.list, todos.delete
});
```

## todos.mjs

```js
import { createRuntime } from '@bitakit/core';
import todos from './todos/plugin.mjs';

const runtime = createRuntime({ plugins: [todos] });
const { actions } = runtime;
const stop = runtime.mount();

try {
  console.log('Delete enabled before:', actions.get('todos.delete').enabled);
  await actions.execute('todos.create', 'Learn plugins');
  await actions.execute('todos.create', 'Connect a service');
  console.log('Delete enabled after:', actions.get('todos.delete').enabled);
  console.log('Before:', (await actions.execute('todos.list')).value);
  await actions.execute('todos.delete', 2);
  console.log('After:', (await actions.execute('todos.list')).value);
} finally {
  stop();
}
```

`createRuntime(config, { actions, services })` creates the ActionList unless you pass one and accepts host-owned services. `mount()` returns the stop function; `runtime.ready` resolves after every service `onStart`.

## Run and inspect

```sh
node todos.mjs
```

The delete action reports `false` before the first task and `true` after it. The first list contains two tasks; after deleting ID 2, the second contains only ID 1. Successful execution returns `{ status: 'completed', value: ... }`. Failed execution rejects; inspect the execution outcome rather than assuming every call ran.

The store is temporary memory. Events notify subscribers after a mutation; they do not hold the task data. Removing a task does not unregister the delete action. Runtime cleanup releases registrations, stores and owned subscriptions.

Try deleting every task: the `enabled` function makes the delete action unavailable once the store is empty. A real product must still validate inputs and authorize mutations on the server.
