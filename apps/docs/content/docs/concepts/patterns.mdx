| You want to                       | Use                                              | Instead of building                                       |
| --------------------------------- | ------------------------------------------------ | --------------------------------------------------------- |
| Request an operation              | [Action](#one-action-several-controls)           | `onClick` handlers with hand-kept `disabled`/`busy` state |

| Trace a service method            | [Service interceptor](#observe-a-service-call)   | Logging added inside each method                          |

## One Action, several controls

```ts
// counter/actions/increment.ts
export default defineAction({
  title: 'Increment',
  execute: ({ services }) => services.counter.value.increment(),
});
```

Import `defineAction` from `@bitakit/core`. Existing bindings reference `counter.increment`;
each call carries its own input. A slot chooses where a control appears.

<Diagram name="action-bindings" />

Use [Action options](/docs/reference/actions) for confirmation, concurrency and feedback.
Native navigation stays a real link; do not also invoke a handler when following it.
See [the Action loop diagram](/docs/concepts/actions#the-action-loop) for the complete
UI → Action → Service → Store → UI cycle.

## Gate or observe an Action

```ts
// counter/interceptors/audit.ts
import { defineInterceptor } from '@bitakit/core';
export default defineInterceptor({
  action: 'counter.increment',
  after: ({ id }) => console.debug('Completed:', id),
});
```

<Diagram name="action-interceptors" />

`before` may be async; `false` skips. `after` and `onError` observe, without replacing results.
See [Action interceptors](/docs/concepts/interceptors#action-interceptors).

## Observe a service call

```ts
// counter/interceptors/calls.ts
import { defineInterceptor } from '@bitakit/core';
export default defineInterceptor({
  service: 'counter.value',
  method: 'increment',
  before: ({ args }) => console.debug('Called with:', args),
});
```

<Diagram name="service-interceptors" />

Internal self-calls bypass the wrapper. See [service interceptors](/docs/concepts/interceptors#service-interceptors).

## Notify other plugins

```ts
// counter/events.ts
import { defineEvents, event } from '@bitakit/core';
export default defineEvents({ incremented: event<number>() });
```

```ts
// Emit in a Counter Action or service; listen in another service factory.
events.emit('counter.incremented', count);
events.on('counter.incremented', ({ data }) => console.log(data));
```

<Diagram name="event-delivery" />

Subscriptions are owned and released. Ordinary emit does not await async handlers;
[cancelable events](/docs/concepts/events#later-cancelable-events) await handlers and report
whether a listener cancelled. Cancellation is coordination, not server authorization.

## Follow current state

```ts
// In a service factory, state is the single owner of the value.
const state = store({ count: 0 });
const increment = () => state.set((s) => ({ count: s.count + 1 }));
```

```tsx
// In a component, read its service; no copied count state or bootstrap effect.
const count = useServiceState('counter.value', (state) => state.count, 0);
```

<Diagram name="service-state" />

See the [service lesson](/docs/concepts/services) for complete files. For persisted preferences,
use `defineSettings` and `useSetting`; the runtime settings store remains the value owner.
