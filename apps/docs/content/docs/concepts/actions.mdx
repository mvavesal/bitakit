**Owner:** definitions and execution in `@bitakit/core`; React bindings in `@bitakit/ui`; router integration in the host adapter.

An action is one operation of your app, defined once. It has an **ID** (its name), a **presentation** (title, icon, shortcut and so on) and **behavior** (`execute`). Buttons, menus, links, keyboard shortcuts and your own code run it through the same guarded executor, and all of them read its current state. You never copy a title or an enabled flag into a component.

All properties and bindings on this page are available in 0.1 and 0.2 unless marked otherwise.

## Start here

Most actions need a title, an `execute` function and one binding. The examples on this page use this service:

```ts
// src/plugins/todos/services/todos.ts
import { defineService } from '@bitakit/core';

export default defineService({
  create({ events }) {
    let tasks: string[] = [];
    const changed = () => events.emit('todos.changed');

    return {
      list: () => [...tasks],
      add(title: string) {
        tasks.push(title);
        changed();
      },
      remove(title: string) {
        tasks = tasks.filter((task) => task !== title);
        changed();
      },
      clear() {
        tasks = [];
        changed();
      },
    };
  },
});
```

### 1. Define the action

```ts
// src/plugins/todos/actions/add.ts
import { defineAction } from '@bitakit/core';

export default defineAction<string>({
  title: 'Add task',
  execute({ app, input }) {
    app.services.todos.add(input);
  },
});
```

`defineAction<string>` declares that the action takes a string as input. The file path gives it the ID `todos.add`. Discovery registers it and adds it to the generated action types, so bindings autocomplete the ID and check the input.

### 2. Bind it

```tsx
// src/components/todos/add-button.tsx
'use client';

import { ActionButton } from '@bitakit/ui';

export function AddButton({ draft }: { draft: string }) {
  return <ActionButton action="todos.add" input={draft} />;
}
```

The button shows the title and passes `draft` as input. It is disabled while the action runs, and errors go to the provider's `onError`.

### 3. Run it from code (optional)

```tsx
// src/components/todos/add-milk-button.tsx
'use client';

import { useFoundationApp } from '@bitakit/ui';

export function AddMilkButton() {
  const app = useFoundationApp();
  const addMilk = () => app.actions.todos.add.execute('Buy milk').catch(() => {});

  return (
    <button type="button" onClick={() => void addMilk()}>
      Add milk
    </button>
  );
}
```

`execute` applies the same checks as the button and returns the [outcome](#execution-status-and-outcomes).

## Properties at a glance

Common properties:

| Property                                                             | Type                                       | Default     | What it does                                                |
| -------------------------------------------------------------------- | ------------------------------------------ | ----------- | ----------------------------------------------------------- |
| [`title`](#title)                                                    | `string`                                   | from the ID | Label of buttons and menu items                             |
| [`description`](#description)                                        | `string`                                   | none        | Longer explanation of what the action does                  |
| [`tooltip`](#tooltip)                                                | `string`                                   | none        | Short hover hint                                            |
| [`icon`](#icon)                                                      | icon component                             | none        | Shown before the title                                      |
| [`variant`](#variant)                                                | `'default' \| 'destructive'`               | `'default'` | Marks a dangerous operation                                 |
| [`enabled`](#enabled)                                                | `boolean`                                  | `true`      | `false`: shown but cannot run                               |
| [`visible`](#visible)                                                | `boolean`                                  | `true`      | `false`: not rendered and cannot run                        |
| [`dependsOn`](#dependson)                                            | `string[]`                                 | none        | Disabled while any listed action is disabled                |
| [`resolve`](#resolve)                                                | `(input, { services, config }) => changes` | none        | Presentation and guards for one input                       |
| [`execute`](#execute)                                                | `(context) => result`                      | none        | The operation itself                                        |
| [`requires`](#requires)                                              | `string[]`                                 | none        | Services from other plugins this action needs               |
| [`success`, `failure`](#success-and-failure)                         | message, `false` or function               | silent      | Message after a run                                         |

| [`shortcut`](#shortcut)                                              | `{ keys, input?, scope?, allowInInputs? }` | none        | Keyboard shortcut                                           |
| [`checked`](#checked)                                                | `boolean`                                  | none        | State of a toggle                                           |
| [`value`](#value)                                                    | any                                        | none        | Selected value of a choice                                  |
| [`metadata`](#metadata)                                              | any                                        | none        | Your own data for custom renderers                          |
| [`unavailable`](#unavailable)                                        | `{ messageKey }`                           | none        | Message `ActionBoundary` shows while the action is disabled |
| [`internal`](#internal)                                              | `boolean`                                  | `false`     | Left out of menus, lists and shortcuts                      |
| [`href`](#url-actions)                                               | `string`                                   | none        | Link target, set through `defineURLAction`                  |

Advanced properties, for special cases:

| Property                                     | Type                    | Default            | What it does                                        |
| -------------------------------------------- | ----------------------- | ------------------ | --------------------------------------------------- |
| [`watch`](#watch)                            | `string[]`              | none               | Observable services that re-evaluate `resolve`      |
| [`events`, `onEvent`](#events-and-onevent)   | event names, handler    | none               | React to app events                                 |
| [`setup`](#setup)                            | `(context) => cleanup?` | none               | Runs once when the action is registered             |
| [`initialState`](#initialstate)              | object                  | none               | State of this registration                          |
| [`id`](#id)                                  | `string`                | from the file path | Explicit ID instead of the path-derived one         |

| [`configPath`](#conventions-and-configpath)  | `string[]`              | from the file path | Config scope of a manually registered action        |

Forms, dialogs and classes add their own properties; see [forms](#forms) and [other kinds of actions](#other-kinds-of-actions).

## Text

`title`, `description` and `tooltip` are three different texts. The title is the label, the description explains the action and the tooltip is a short hint on hover. Set only the ones you need.

### `title`

The label of buttons, links and menu items:

```ts
// src/plugins/todos/actions/add.ts
import { defineAction } from '@bitakit/core';

export default defineAction<string>({
  title: 'Add task',
  execute: ({ app, input }) => app.services.todos.add(input),
});
```

The displayed text is the first match of:

1. `title` as a translation key, for example `title: 'todos.addTask'`;
2. the key `<id>.title`, here `todos.add.title`;
3. `title` as written.

Without `title`, the key `<id>.title` is tried and then a title made from the last part of the ID: `todos.clear-done` becomes "Clear done". Titles update when the language changes.

Translation needs a translator. Pass one to your provider's `translate` prop; without it, titles are shown as written:

```ts
// src/i18n/translate.ts
import type { Translator } from '@bitakit/core';

const german: Record<string, string> = { 'todos.add.title': 'Aufgabe hinzufügen' };

// todos.add now shows "Aufgabe hinzufügen"; actions without an entry keep their title.
export const translate: Translator = Object.assign((key: string) => german[key] ?? key, {
  has: (key: string) => key in german,
});
```

### `description`

A longer explanation of what the action does, for example in a list of actions or as help text:

```ts
// src/plugins/todos/actions/clear.ts
import { defineAction } from '@bitakit/core';

export default defineAction({
  title: 'Clear all',
  description: 'Removes every task from the list. Completed and open tasks are both removed.',
  execute: ({ app }) => app.services.todos.clear(),
});
```

Buttons, links and menu items show it as hover text when there is no tooltip, and custom renderers read it from the snapshot. Translation works like `title`: the value as a key, then `<id>.description`, then the text. Without `description`, no key is looked up.

### `tooltip`

A short hint on hover. It is not a shorter description:

```ts
// src/plugins/todos/actions/clear.ts
import { defineAction } from '@bitakit/core';

export default defineAction({
  title: 'Clear all',
  tooltip: 'This cannot be undone',
  execute: ({ app }) => app.services.todos.clear(),
});
```

`ActionButton`, `ActionLink`, menu items and `ActionBinding` show the tooltip on hover, or the description when there is no tooltip. A `title` prop you pass to the button or link wins. Translation: the value as a key, then `<id>.tooltip`, then the text.

## Appearance

### `icon`

Any React component that accepts `className` and `aria-hidden`, for example from your icon library:

```ts
// src/plugins/todos/actions/add.ts
import { defineAction } from '@bitakit/core';
import Plus from 'reicon-react/icons/Plus';

export default defineAction<string>({
  title: 'Add task',
  icon: Plus,
  execute: ({ app, input }) => app.services.todos.add(input),
});
```

`ActionButton` and menu items render it before the title and hide it from screen readers. Core only stores it.

### `variant`

`'destructive'` marks a dangerous operation:

```ts
// src/plugins/todos/actions/clear.ts
import { defineAction } from '@bitakit/core';

export default defineAction({
  title: 'Clear all',
  variant: 'destructive',
  execute: ({ app }) => app.services.todos.clear(),
});
```

Menu items use the destructive style. `ActionButton` does not change its look by itself; pass your button's own prop: `<ActionButton action="todos.clear" as={Button} variant="destructive" />`.

## Availability

Three separate states decide whether an action can run:

|           | Who sets it                                | Meaning                      | The control           | Running it                     |
| --------- | ------------------------------------------ | ---------------------------- | --------------------- | ------------------------------ |
| `enabled` | you: definition, `resolve`, events, config | `false`: not available now   | shown, disabled       | skipped with reason `disabled` |
| `visible` | you: definition, `resolve`, events, config | `false`: not offered here    | not rendered          | skipped with reason `hidden`   |
| `pending` | the runtime                                | `true`: a run is in progress | disabled, `aria-busy` | skipped with reason `pending`  |

None of them is security: the server still checks permissions.

### `enabled`

`enabled: false` shows the control disabled. The value is where the action starts; change it later, for example from an event:

```ts
// src/plugins/todos/actions/clear.ts
import { defineAction } from '@bitakit/core';

export default defineAction({
  title: 'Clear all',
  enabled: false, // nothing to clear yet
  events: ['todos.changed'],
  onEvent(_event, { app, action }) {
    action.enabled = app.services.todos.list().length > 0;
  },
  execute: ({ app }) => app.services.todos.clear(),
});
```

For a check that depends on the input, use [`resolve`](#resolve). The app can also switch an action off with `actions.overrides` in its configuration; see [overrides](/docs/concepts/overrides).

### `visible`

`visible: false` removes the action from the UI: bindings render nothing and menus leave it out:

```ts
// src/plugins/todos/actions/clear.ts
import { defineAction } from '@bitakit/core';

export default defineAction({
  title: 'Clear all',
  visible: false, // hidden until there is something to clear
  events: ['todos.changed'],
  onEvent(_event, { app, action }) {
    action.visible = app.services.todos.list().length > 0;
  },
  execute: ({ app }) => app.services.todos.clear(),
});
```

Use `enabled` for "not now" and `visible` for "not here".

### `pending`

`pending` is not a property you set. The runtime sets it to `true` while a run is in progress and back to `false` when the run ends. During that time bindings disable themselves and another run of the same action is skipped. Read it with [`useAction`](#useaction) when you build your own control.

### `dependsOn`

Makes the action's availability depend on other actions: while any listed action is disabled, this action is disabled too.

```ts
// src/plugins/todos/actions/export.ts
import { defineAction } from '@bitakit/core';

export default defineAction({
  title: 'Export tasks',
  // Disabled whenever todos.clear is disabled. Export never runs todos.clear.
  dependsOn: ['todos.clear'],
  execute: ({ app }) => JSON.stringify(app.services.todos.list()),
});
```

- It never runs the listed actions.
- It does not check whether they ran or succeeded before.
- A missing ID or a cycle disables the action.

Each listed action counts with its own `enabled`, `resolve` and `dependsOn`, evaluated with the same input.

### `resolve`

`resolve(input, { services, config })` returns presentation changes for one input. Each binding passes its own input, so two buttons of one action can show different titles or availability:

```ts
// src/plugins/todos/actions/add.ts
import { defineAction } from '@bitakit/core';

export default defineAction<string>({
  title: 'Add task',
  resolve: (title) => ({
    // resolve also runs without input, for example for menus, so title can be undefined.
    enabled: Boolean(title?.trim()),
    title: title ? `Add "${title}"` : 'Add task',
  }),
  execute: ({ app, input }) => app.services.todos.add(input.trim()),
});
```

`<ActionButton action="todos.add" input={draft} />` is now disabled while `draft` is empty and shows the text it will add.

`resolve` can return `title`, `description`, `tooltip`, `icon`, `href`, `enabled`, `visible`, `checked`, `value` and `variant`. The result applies to that binding only, never to the shared registration. A `false` from `resolve` also blocks running the action with that input. Keep it fast and free of side effects, and do not throw.

The second argument has `services` and `config`; there is no `app`. Address services by their ID, for example `services['todos.todos']`. Core 0.2 also accepts the public name, `services.todos`.

## Running

### `execute`

The operation itself. It receives one context object:

| Field           | What it is                                                                                    |
| --------------- | --------------------------------------------------------------------------------------------- |
| `input`         | The value the binding or caller passed; its type is `defineAction<Input>`                     |
| `app`           | The app: `app.services`, `app.actions`, `app.events`, `app.config`                            |
| `services`      | Services by ID, for example `services['todos.todos']`; 0.2 also accepts public names          |
| `config`        | `config.plugin` and `config.action` scopes; see [configuration](/docs/concepts/configuration) |
| `id`            | This action's ID                                                                              |
| `get()`         | The current snapshot of this registration                                                     |
| `update(patch)` | Changes this registration, for example `update({ checked: true })`                            |
| `environment`   | Host navigation and dependency injection; rarely needed                                       |

```ts
// src/plugins/todos/actions/add.ts
import { defineAction } from '@bitakit/core';

export default defineAction<string, number>({
  title: 'Add task',
  async execute({ input, app, config }) {
    const limit = config.action.get('limit', 100);
    if (app.services.todos.list().length >= limit) throw new Error('Task limit reached.');
    app.services.todos.add(input);
    return app.services.todos.list().length; // the caller receives this value
  },
});
```

What you return reaches the caller as `{ status: 'completed', value }`. With an explicit input type, also name the result type, as in `defineAction<string, number>`; without type arguments both are inferred. Throwing makes the run fail: the status becomes `failed`, the snapshot's `error` holds the error and the caller's promise rejects. `execute` may be async. An action without `execute` is skipped with the reason `no-handler`.

### `requires`

Lists services from **other** plugins that the action uses:

```ts
// src/plugins/reports/actions/export.ts
import { defineAction } from '@bitakit/core';

export default defineAction({
  title: 'Export report',
  // The todos service belongs to another plugin, so declare it.
  requires: ['todos.todos'],
  execute: ({ app }) => app.services.todos.list().join('\n'),
});
```

`todos.todos` is the service ID: `<plugin>.<service file>`. Core 0.2 also accepts the public name, `todos`. At startup the app checks that each listed service exists. If one is missing, startup fails with an error that names this action. In development (0.2), the plugin is turned off instead and a dialog explains why. Services of the action's own plugin are always available; do not list them.

### `success` and `failure`

Optional messages after a run. Without them, actions are silent:

```ts
// src/plugins/todos/actions/add.ts
import { defineAction } from '@bitakit/core';

export default defineAction<string>({
  title: 'Add task',
  execute: ({ app, input }) => app.services.todos.add(input),
  success: ({ input }) => `Added "${input}"`,
  failure: 'Could not add the task.',
});
```

Each accepts:

| Value                             | Meaning                                                                                              |
| --------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `'Text'`                          | The text; it is tried as a translation key, then `<id>.success` or `<id>.failure`                    |
| `{ messageKey, values }`          | A translation key with values, for example `{ messageKey: 'todos.added', values: { title: input } }` |
| `{ message, closeDialog: false }` | Text that keeps a form dialog open                                                                   |
| `false` or omitted                | No message                                                                                           |
| a function                        | Receives `{ result, input, services }` or `{ error, input, services }` and returns one of the above  |

The success message goes to your provider's `notify(message, kind)` callback, for example a toast. The failure message is shown inside form dialogs. Other bindings receive an `ActionFailure` in `onError`: its `message` is the failure text and its `cause` is the original error. Messages never change the outcome of a run.

## Keyboard

### `shortcut`

```ts
// src/plugins/todos/actions/add.ts
import { defineAction } from '@bitakit/core';

export default defineAction<string>({
  title: 'Add task',
  shortcut: { keys: 'Mod+Shift+N', input: 'New task' },
  execute: ({ app, input }) => app.services.todos.add(input),
});
```

| Field           | Meaning                                                                                                                       |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `keys`          | [TanStack Hotkeys](https://tanstack.com/hotkeys/latest/docs/overview) syntax; `Mod` is Command on macOS and Control elsewhere |
| `input`         | Passed when the shortcut runs; required when the input type does not allow `undefined`                                        |
| `scope`         | The shortcut works only while the provider activates this scope; default `global`                                             |
| `allowInInputs` | Also run while typing in an input, textarea, select or editable element; off by default                                       |

Shortcuts work without a rendered button and use the same guarded execution: nothing happens while the action is hidden, disabled or running. If two actions use the same keys, the first keeps them and the conflict is reported to `onError`. Menu items show the keys automatically; elsewhere use `<ActionShortcutLabel keys="Mod+Shift+N" />` from `@bitakit/ui`.

A scoped shortcut needs its scope activated on the provider:

```ts
shortcut: { keys: 'Mod+Enter', scope: 'editor', allowInInputs: true },
```

```tsx
<FoundationProvider actionOptions={{ shortcuts: { scopes: ['global', 'editor'] } }}>
  {children}
</FoundationProvider>
```

## Toggles and choices

### `checked`

The state of a toggle. `ActionCheckbox` shows it and runs the action with the new value; the action stores it with `update`:

```ts
// src/plugins/todos/actions/show-done.ts
import { defineAction } from '@bitakit/core';

export default defineAction<boolean>({
  title: 'Show completed',
  checked: false,
  execute: ({ input, update }) => {
    update({ checked: input });
  },
});
```

```tsx
// src/components/todos/show-done-toggle.tsx
'use client';

import { ActionCheckbox, useAction } from '@bitakit/ui';

export function ShowDoneToggle() {
  const showDone = useAction('todos.show-done')?.checked ?? false;
  return (
    <>
      <ActionCheckbox action="todos.show-done" />
      <p>{showDone ? 'Completed tasks are shown.' : 'Completed tasks are hidden.'}</p>
    </>
  );
}
```

`ActionButton` exposes `checked` as `aria-pressed`, so a button can act as a toggle too.

### `value`

The selected value of a choice. `ActionRadioGroup` shows it and runs the action with the chosen option:

```ts
// src/plugins/todos/actions/sort.ts
import { defineAction } from '@bitakit/core';

export default defineAction<string>({
  title: 'Sort by',
  value: 'newest',
  execute: ({ input, update }) => {
    update({ value: input });
  },
});
```

```tsx
<ActionRadioGroup
  action="todos.sort"
  options={[
    { value: 'newest', label: 'Newest first' },
    { value: 'title', label: 'Title' },
  ]}
/>
```

## Other properties

### `metadata`

Your own data. Core stores it unchanged and never reads it; a custom renderer decides what it means:

```ts
// src/plugins/todos/actions/clear.ts
import { defineAction } from '@bitakit/core';

export default defineAction({
  title: 'Clear all',
  metadata: { confirm: 'Remove every task?' },
  execute: ({ app }) => app.services.todos.clear(),
});
```

```tsx
// src/components/todos/confirm-button.tsx
'use client';

import { useAction } from '@bitakit/ui';

export function ConfirmButton({ action }: { action: string }) {
  const state = useAction(action);
  if (!state?.visible) return null;
  const { confirm } = (state.metadata ?? {}) as { confirm?: string };

  return (
    <button
      type="button"
      disabled={!state.enabled || state.pending}
      onClick={() => {
        if (!confirm || window.confirm(confirm)) state.execute().catch(() => {});
      }}
    >
      {state.title}
    </button>
  );
}
```

### `unavailable`

A translation key that `ActionBoundary` shows while the action is disabled:

```ts
// src/plugins/todos/actions/share.ts
import { defineAction } from '@bitakit/core';

export default defineAction({
  title: 'Share list',
  enabled: false, // enabled once sharing is configured
  unavailable: { messageKey: 'todos.share.unavailable' },
  execute: ({ app }) => navigator.clipboard.writeText(app.services.todos.list().join('\n')),
});
```

```tsx
<ActionBoundary action="todos.share" fallback={(message) => <p>{message}</p>}>
  <ShareOptions />
</ActionBoundary>
```

`ActionBoundary` renders its children while the action is enabled, nothing while it is hidden, and otherwise the translated message (or `fallback`). It is a UI gate, not authorization. When you also set `metadata`, it must be an object.

### `internal`

`internal: true` keeps a helper action out of `useActions`, menus, groups and shortcuts:

```ts
// src/plugins/todos/actions/import.ts
import { defineAction } from '@bitakit/core';

export default defineAction<string[]>({
  internal: true, // run from code only
  execute: ({ app, input }) => input.forEach((title) => app.services.todos.add(title)),
});
```

Run it by ID through the action list: `useActionList().execute('todos.import', ['Buy milk'])`. Typed references such as `app.actions.todos.import` refuse internal actions.

## Groups

Put related actions under one name with `groups`:

```ts
// src/plugins/todos/actions/clear.ts
import { defineAction } from '@bitakit/core';

export default defineAction({
  title: 'Clear all',
  groups: ['todos.bulk'],
  execute: ({ app }) => app.services.todos.clear(),
});
```

A group only groups. Components read it and decide how to show it: `ActionMenu` as a dropdown, the app's navigation as a sidebar, search as a heading. [Action groups](/docs/concepts/action-groups) explains titles, which components use groups, and order and separators.

## Forms

A form collects values and an action receives them as input. The form can sit on a page, in a dialog or inside a larger form; the action stays the same.

### A form on a page

Build the form with your form library and run an ordinary action with the validated values. This example uses react-hook-form and zod, the libraries of the reference app; any form library works the same way.

```ts
// src/plugins/todos/schema.ts
import { z } from 'zod';

export const taskSchema = z.object({
  title: z.string().trim().min(1, 'Enter a title.'),
});
export type TaskInput = z.infer<typeof taskSchema>;
```

```ts
// src/plugins/todos/actions/create.ts
import { defineAction } from '@bitakit/core';
import { taskSchema, type TaskInput } from '../schema';

export default defineAction<TaskInput>({
  title: 'Create task',
  execute({ app, input }) {
    // Actions can also run from code or shortcuts, so validate the input here too.
    const task = taskSchema.parse(input);
    app.services.todos.add(task.title);
  },
});
```

```tsx
// src/plugins/todos/components/task-form.tsx
'use client';

import { useState } from 'react';
import { useForm } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';
import { useAction } from '@bitakit/ui';
import { taskSchema, type TaskInput } from '../schema';

export function TaskForm({ onCreated }: { onCreated?: () => void }) {
  const create = useAction('todos.create');
  const form = useForm<TaskInput>({
    resolver: zodResolver(taskSchema),
    defaultValues: { title: '' },
  });
  const [error, setError] = useState<string>();

  const submit = form.handleSubmit(async (values) => {
    setError(undefined);
    try {
      const outcome = await create?.execute(values);
      if (outcome?.status !== 'completed') return;
      form.reset();
      onCreated?.();
    } catch (failure) {
      // The values stay in the form, so the user can correct them and retry.
      setError(failure instanceof Error ? failure.message : 'Could not create the task.');
    }
  });

  if (!create?.visible) return null;
  const titleError = form.formState.errors.title?.message;

  return (
    <form onSubmit={submit} noValidate>
      <label htmlFor="task-title">Title</label>
      <input id="task-title" aria-invalid={Boolean(titleError)} {...form.register('title')} />
      {titleError && <p role="alert">{titleError}</p>}
      {error && <p role="alert">{error}</p>}
      <button type="submit" disabled={!create.enabled || create.pending}>
        {create.pending ? 'Saving…' : create.title}
      </button>
    </form>
  );
}
```

What you get:

- **No popup:** the form submits on the page.
- **Input:** the validated values are the action's input, typed by `defineAction<TaskInput>`.
- **Pending:** while the action runs, `create.pending` disables the button, and a second submit is skipped with the reason `pending`.
- **Errors keep the draft:** a failure rejects `execute`; the form shows the message and keeps the values for a retry. It resets only after a `completed` outcome.

For a section of a larger form, do not nest `<form>` elements. Validate the section's fields, for example with react-hook-form's `trigger`, and run the section's action from a `type="button"` with those values.

### Quick dialog forms: `defineFormAction`

`defineFormAction` describes a small form as data and always shows it in the shared dialog. It suits short prompts such as an invitation by email. Its values are strings, and its validation is limited to required fields, the email format and select options. For page forms, sections of larger forms, custom validation or other value types, use an ordinary action as shown above.

```ts
// src/plugins/todos/actions/new-task.ts
import { defineFormAction } from '@bitakit/core';

export default defineFormAction({
  title: 'New task',
  fields: {
    title: { type: 'text', label: 'Title', required: true },
    owner: { type: 'email', label: 'Owner email' },
    priority: {
      type: 'select',
      label: 'Priority',
      defaultValue: 'normal',
      options: [
        { value: 'normal', label: 'Normal' },
        { value: 'high', label: 'High' },
      ],
    },
  },
  submit(values, { services }) {
    const title = values.priority === 'high' ? `${values.title} (high)` : values.title;
    services['todos.todos'].add(title);
  },
  success: ({ input }) => `Created "${input.title}"`,
  closeOnSuccess: false, // keep the form open to add several tasks
});
```

| Property             | Meaning                                                                                                     |
| -------------------- | ----------------------------------------------------------------------------------------------------------- |
| `fields`             | Field name → `{ type: 'text' \| 'email' \| 'select', label?, required?, defaultValue?, options? }`          |
| `submit`             | `(values, { services, config, input })`; `values` has one string per field; `input` is what opened the form |
| `success`, `failure` | As above; the context's `input` is the submitted values                                                     |
| `closeOnSuccess`     | `false` keeps the dialog open after a successful submit; the default closes it                              |
| `render`             | Optional custom form body; receives `values`, `setValue`, `submit`, `pending`, `enabled` and `error`        |

Running the action opens the form. Submitting validates the fields and calls `submit` through an internal action, so interceptors and pending state apply to it too. A `label` is tried as a translation key; without `label`, the key `<id>.fields.<name>` is tried, then the field name.

### Dialog actions

A dialog with your own content:

```tsx

export default defineDialogAction<string>({

      </button>
```

`render` receives `input`, `close` and `services`. `size` is `'default'` or `'wide'`. `resolve` and `watch` work as for plain actions. Bind it like any action: `<ActionButton action="todos.details" input={task} />`.

### Class actions

A class extending `Action`, for behavior that spans several methods. The app passes `{ services, translate, config }` to the constructor:

```ts
// src/plugins/todos/actions/duplicate.ts
import { Action, type ActionEnvironment } from '@bitakit/core';

export default class DuplicateTask extends Action<string> {
  private services: ActionEnvironment['services'];

  constructor({ services }: ActionEnvironment) {
    super({ title: 'Duplicate' });
    this.services = services;
  }

  isEnabled(title: string) {
    return Boolean(title);
  }

  execute(title: string) {
    this.services['todos.todos'].add(`${title} (copy)`);
  }
}
```

The constructor options take the presentation properties (`id`, `title`, `description`, `tooltip`, `icon`, `variant`, `enabled`, `visible`, `dependsOn`, `checked`, `value`, `shortcut`, `order`, `dividerBefore`, `metadata`), an optional `execute` and opt-in `success` and `failure` messages. `groups` must be `ActionGroup` objects. There is no `requires`, `watch`, `events` or `setup`. `isEnabled(input)`, `isVisible(input)` and `getPresentation(input)` play the role of `resolve`. Discovery gives the class an ID from its path (`todos.duplicate`), but classes do not add entries to the generated action types: bind them with the string ID.

## Bindings

### How binding works

A binding connects a control to an action by ID. It never copies the action:

1. **Register.** At startup each action is registered once in the app's action list. Each registration has a live snapshot: its properties plus `enabled`, `visible`, `pending`, `status`, `error` and `state`.
2. **Subscribe.** A binding looks up the action by ID or typed reference and re-renders when the snapshot changes: after `update`, an event handler's change, a watched service notification or a language switch.
3. **Resolve.** The binding evaluates `resolve` and `dependsOn` with its own input. That is why one registration can serve every row of a table.
4. **Run.** Activating the control calls `execute(id, input)` on the action list. The executor checks again that the action exists, is visible, enabled, not running and has a handler; then interceptors run, then your `execute`. While it runs, `pending` is `true` and bindings disable themselves.
5. **Finish.** The status becomes `succeeded` or `failed`. Success feedback goes to `notify`; a failure goes to the binding's `onError`.

All bindings come from `@bitakit/ui` and must be rendered inside your app's `FoundationProvider`. A binding of a missing or hidden action renders nothing.

### `ActionButton`

```tsx
// src/components/todos/toolbar.tsx
'use client';

import { ActionButton } from '@bitakit/ui';
import { Button } from '@bitakit/ui/components';

export function Toolbar({ draft }: { draft: string }) {
  return (
    <div>
      {/* A native <button>; the label is the action's title. */}
      <ActionButton action="todos.add" input={draft} />

      {/* Your button component; other props such as variant are passed through. */}
      <ActionButton action="todos.add" input={draft} as={Button} variant="outline">
        Add
      </ActionButton>

      <ActionButton
        action="todos.clear"
        as={Button}
        variant="destructive"
        onError={(error) => window.alert(error instanceof Error ? error.message : String(error))}
      />
    </div>
  );
}
```

| Prop        | Meaning                                                                  |
| ----------- | ------------------------------------------------------------------------ |
| `action`    | Action ID or typed reference                                             |
| `input`     | Passed to `resolve` and `execute`                                        |
| `as`        | Component to render; default a native `button`                           |
| `onError`   | Receives failures; default is the provider's `onError` (`console.error`) |
| `children`  | Label; default is the title, or "Working…" while running                 |
| other props | Passed to the component, for example `variant`, `size` or `className`    |

It sets `type="button"`, `disabled` (not enabled, running or your own `disabled`), `aria-busy` while running, `aria-pressed` from `checked`, the tooltip (or the description) as hover text and the icon before the label. Presentation from `resolve` uses the button's own `input`.

### `ActionLink`

Renders a URL action as a real link:

```tsx
<ActionLink action="todos.open" />
<ActionLink action="todos.open" className="underline">
  My tasks
</ActionLink>
```

Internal paths use the router's link component, external `http(s)` URLs a plain `<a>`. Clicking follows the link natively, so new-tab and copy-link work, and no handler runs twice. While the action is disabled or running, it renders an `<a aria-disabled="true">` without `href`. `as` replaces the link component.

Without `as`, a native checkbox with the title as label. With `as`, your component receives `checked`, `disabled`, `aria-label` and `onCheckedChange(value)`, which fits shadcn's `Checkbox` and `Switch`. See [`checked`](#checked) for the action side.

### `ActionRadioGroup`

```tsx
<ActionRadioGroup

    { value: 'newest', label: 'Newest first' },
```

Without `as`, a `fieldset` with the title as legend and one radio per option. With `as`, your component receives `value`, `disabled`, `options` and `onValueChange(value)`. See [`value`](#value) for the action side.

### `ActionMenu`

Renders a [group](/docs/concepts/action-groups) as a menu with your app's menu component:


### `ActionGroupBinding`

Renders groups with your own component and passes one input, `context`, to every item. This is the pattern for row actions: one registration, rendered once per row:

```ts
  variant: 'destructive',

```

```tsx
// src/components/todos/task-row.tsx
'use client';

import { ActionGroup, ActionGroupBinding, type ActionGroupsViewProps } from '@bitakit/ui';

const rowActions = new ActionGroup<string>('todos.row');

function RowButtons({ groups }: ActionGroupsViewProps) {
  return (
    <>
      {groups
        .flatMap((group) => group.items)
        .map((item) => (
          <button
            key={item.id}
            type="button"
            disabled={item.disabled}
            onClick={() => item.run().catch(() => {})}
          >
            {item.title}
          </button>
        ))}
    </>
  );
}

export function TaskRow({ title }: { title: string }) {
  return (
    <li>
      {title} <ActionGroupBinding groups={[rowActions]} context={title} as={RowButtons} />

  );

```

Each item is the resolved snapshot for `context` plus `disabled` and `run(input?)`. Hidden items and empty groups are left out.

### `ActionBinding`

A render prop for any control:

```tsx
// src/components/todos/add-form.tsx
'use client';

import { useState } from 'react';
import { ActionBinding } from '@bitakit/ui';

export function AddForm() {
  const [draft, setDraft] = useState('');

  return (
    <ActionBinding action="todos.add" input={draft}>
      {({ title, disabled, pending, execute }) => (
        <form
          onSubmit={(event) => {
            event.preventDefault();
            void execute();
          }}
        >
          <input value={draft} onChange={(event) => setDraft(event.target.value)} />
          <button type="submit" disabled={disabled}>
            {pending ? 'Adding…' : title}
          </button>
        </form>
      )}
    </ActionBinding>
  );
}
```

The function receives `title`, `description`, `disabled`, `pending`, `checked`, `value`, `selected` and `execute(input?)`. `execute` never rejects; failures go to `onError`. `kind` decides `selected`: `'toggle'` uses `checked`, `'choice'` compares `value` with the input. The output is wrapped in an element with `display: contents` that carries the tooltip. When you need the outcome, for example to reset a form only after success, use [`useAction`](#useaction) as in the [form example](#a-form-on-a-page).

### `useAction`

The resolved snapshot and a guarded `execute`, for full control:

```tsx
// src/components/todos/add-with-status.tsx
'use client';

import { ActionStatus, useAction } from '@bitakit/ui';

export function AddWithStatus({ draft }: { draft: string }) {
  const add = useAction('todos.add', draft);
  if (!add?.visible) return null;

  return (
    <button
      type="button"
      disabled={!add.enabled || add.pending}
      onClick={() => add.execute().catch(() => {})}
    >
      {add.title}
      {add.status === ActionStatus.Failed && ' (failed, try again)'}
    </button>
  );
}
```

`useAction(action, input?)` returns `undefined` for an unknown ID. The result has every snapshot field, resolved for `input`, and `execute(input?)`, which returns the [outcome](#execution-status-and-outcomes) and rejects when the run fails.

### Typed references

`app.actions` mirrors the action IDs: `app.actions.todos.add` is a typed reference to the action `todos.add`. You can use a reference in two ways. Both buttons below add the same task:

```tsx
// src/components/todos/add-task-buttons.tsx
'use client';

import { ActionButton, useFoundationApp } from '@bitakit/ui';

export function AddTaskButtons() {
  const app = useFoundationApp();
  const addTask = app.actions.todos.add; // typed reference to "todos.add"

  const addFromCode = async () => {
    const outcome = await addTask.execute('Buy milk');
    if (outcome.status === 'skipped') console.info('Not added:', outcome.reason);
  };

  return (
    <>
      {/* 1. In a binding: the reference replaces the string "todos.add". */}
      <ActionButton action={addTask} input="Buy milk" />

      {/* 2. From your own code: run it and read the outcome. */}
      <button type="button" onClick={() => void addFromCode().catch(() => {})}>
        Add from code
      </button>
    </>
  );
}
```

A misspelled reference is a compile error. A misspelled string ID only loses autocompletion, unless you turn on [strict action IDs](/docs/concepts/type-safety#strict-action-ids).

IDs with dashes use brackets: `app.actions.todos['show-done']`. A reference belongs to its app instance; passing it to another provider fails. Outside React, use `runtime.actions.execute('todos.add', 'Buy milk')`; in plugin tests, `mountPlugin` from `@bitakit/core/testing` (0.2).

### `useActions`

All public action snapshots, for lists such as a command palette:

```tsx
// src/components/todos/all-actions.tsx
'use client';

import { useActions } from '@bitakit/ui';

export function AllActions() {
  const actions = useActions();

  return (
    <ul>

        .filter((action) => action.visible)
        .map((action) => (
          <li key={action.id}>
            {action.title} <code>{action.id}</code>
          </li>
        ))}

```

These snapshots have no input; use `useAction(id, input)` for input-specific presentation. `useActions({ internal: true })` includes internal actions.

### Register from a component

Most actions are files. An action that only exists while a component is mounted can be registered from it:

```tsx
// src/components/editor/editor-actions.tsx
'use client';

import { useMemo } from 'react';
import { useRegisterActions, type ActionDefinition } from '@bitakit/ui';

export function EditorActions({ save }: { save: () => void }) {
  const actions = useMemo<ActionDefinition[]>(
    () => [
      {
        id: 'editor.save',
        title: 'Save',
        shortcut: { keys: 'Mod+Shift+S', allowInInputs: true },
        execute: () => save(),
      },
    ],
    [save],
  );
  useRegisterActions(actions);
  return null;
}
```

The actions are removed when the component unmounts. Memoize the list: a new array registers the actions again. These definitions use the low-level format: `id` and `title` are required, and `execute` receives the plain [`execute` context](#execute) without `app`, `services` or `config`.

## Execution status and outcomes

The snapshot's `status` describes the last run of a registration:

| Status                   | Meaning                                     |
| ------------------------ | ------------------------------------------- |
| `ActionStatus.Idle`      | Not run since it was registered             |
| `ActionStatus.Pending`   | Running; `pending` is `true`                |
| `ActionStatus.Succeeded` | The last run finished; `error` is cleared   |
| `ActionStatus.Failed`    | The last run threw; `error` holds the error |

Running an action resolves to an outcome:

| Outcome                          | Meaning                                         |
| -------------------------------- | ----------------------------------------------- |
| `{ status: 'completed', value }` | It ran; `value` is what `execute` returned      |
| `{ status: 'skipped', reason }`  | It did not run; status and error stay unchanged |
| rejected promise                 | `execute` threw                                 |

Skip reasons: `missing` (unknown ID), `hidden`, `disabled`, `pending` (already running), `no-handler`, `intercepted` (an [interceptor](/docs/concepts/interceptors) refused) and `replaced` (the registration changed while starting). Bindings handle all three outcomes for you; when you call `execute` yourself, check the outcome and catch failures.

## Advanced: lifecycle and reactivity

Most actions do not need this section. These options keep an action in sync with changes elsewhere in the app. Choose by the source of the change:

| Need                                                | Use                    | What it updates                     |
| --------------------------------------------------- | ---------------------- | ----------------------------------- |
| Availability or text depends on the binding's input | [`resolve`](#resolve)  | each binding separately             |
| An observable service changed                       | `watch` with `resolve` | each binding (`resolve` runs again) |
| A named event happened                              | `events` and `onEvent` | the shared registration             |
| Initial check, timers or external subscriptions     | `setup`                | the shared registration             |
| Counters or flags that belong to the action         | `initialState`         | the shared registration             |

`watch` and events can serve the same goal but update different things: `watch` makes every binding evaluate its own `resolve` again, while `onEvent` and `setup` write one shared value, such as `action.enabled`, for all bindings.

### `watch`

Lists **observable** services: services with a `subscribe(listener)` method. When one notifies, every binding evaluates `resolve` again:

```ts
// src/plugins/todos/services/selection.ts
import { defineService } from '@bitakit/core';

export default defineService({
  create() {
    let selected: string[] = [];
    const listeners = new Set<() => void>();

    return {
      get: () => selected,
      set(titles: string[]) {
        selected = titles;
        listeners.forEach((listener) => listener());
      },
      // This method makes the service observable.
      subscribe(listener: () => void) {
        listeners.add(listener);
        return () => {
          listeners.delete(listener);
        };
      },
    };
  },
});
```

```ts
// src/plugins/todos/actions/remove-selected.ts
import { defineAction } from '@bitakit/core';

export default defineAction({
  title: 'Remove selected',
  watch: ['todos.selection'],
  resolve: (_input, { services }) => ({
    enabled: services['todos.selection'].get().length > 0,
  }),
  execute: ({ app }) => {
    for (const title of app.services.selection.get()) app.services.todos.remove(title);
    app.services.selection.set([]);
  },
});
```

A watched service without `subscribe` stops startup with an error.

### `events` and `onEvent`

React to named [events](/docs/concepts/events) with one handler. The handler receives the event and the same context as `setup`, plus an `AbortSignal`:

```ts
// src/plugins/todos/actions/clear.ts
import { defineAction } from '@bitakit/core';

export default defineAction({
  title: 'Clear all',
  events: ['todos.changed'],
  onEvent(_event, { app, action }) {
    const count = app.services.todos.list().length;
    action.enabled = count > 0;
    action.title = count > 0 ? `Clear all (${count})` : 'Clear all';
  },
  execute: ({ app }) => app.services.todos.clear(),
});
```

`action` can set `enabled`, `visible`, `checked`, `value`, `title`, `description`, `tooltip`, `icon`, `href` and `variant`. Events do not replay: the handler first runs at the next event, so check the initial state in `setup`.

### `setup`

Runs once when the action is registered. Use it for the initial state and for subscriptions:

```ts
// src/plugins/todos/actions/clear.ts
import { defineAction } from '@bitakit/core';

export default defineAction({
  title: 'Clear all',
  setup({ services, action, events }) {
    const refresh = () => {
      action.enabled = services['todos.todos'].list().length > 0;
    };
    refresh(); // events do not replay, so check once at startup
    events.watch(['todos.changed'], refresh); // removed automatically

    const timer = setInterval(refresh, 60_000);
    return () => clearInterval(timer); // your own resources: return a cleanup
  },
  execute: ({ app }) => app.services.todos.clear(),
});
```

The context has `app`, `services`, `config`, `events` and `action`. Setup runs while the app is still starting, so use `services` here; `app.services` throws until startup has finished. Subscriptions made with `events.watch` end with the registration. Return a cleanup function for anything else you start.

### `initialState`

State that belongs to this registration, shared by all its bindings and not saved anywhere. Use the curried form `defineAction<Input>()({...})`; `this` in `execute` then has `state`, `app`, `services` and `config`:

```ts
// src/plugins/todos/actions/quick-add.ts
import { defineAction } from '@bitakit/core';

export default defineAction<string>()({
  title: 'Quick add',
  initialState: { added: 0 },
  execute(title) {
    this.app.services.todos.add(title);
    this.state.update((current) => ({ added: current.added + 1 }));
  },
});
```

```tsx
// src/components/todos/quick-add-count.tsx
'use client';

import { useAction } from '@bitakit/ui';

export function QuickAddCount() {
  const added = useAction('todos.quick-add')?.state.added ?? 0;
  return <p>Added with Quick add: {added}</p>;
}
```

Use method syntax (`execute(title) {}`) so `this` is bound. Each registration starts with a copy of `initialState`; updates after the action is removed are ignored. Keep data that must survive in a service.

## Advanced: identity, discovery and configuration

Discovery derives IDs, translation keys and config scopes from file paths. These options override that when you need to.

### `id`

The ID is the action's name. Bindings, shortcuts, `dependsOn`, overrides and tests refer to the action by its ID. With discovery, the plugin folder and the file path build it:

| File                                       | ID                  |
| ------------------------------------------ | ------------------- |
| `src/plugins/todos/actions/add.ts`         | `todos.add`         |
| `src/plugins/todos/actions/tasks/clear.ts` | `todos.tasks.clear` |
| `src/actions/reset.ts` (app action)        | `reset`             |

Set `id` when the name must stay the same after you move or rename the file. It is used exactly as written; no plugin prefix is added:

```ts
// src/plugins/todos/actions/add.ts
import { defineAction } from '@bitakit/core';

export default defineAction<string>({
  id: 'todos.add', // stays "todos.add" even if this file moves
  execute: ({ app, input }) => app.services.todos.add(input),
});
```

An ID starts with a letter or digit and may contain letters, digits, `.`, `_`, `:`, `/` and `-`. It is unique in the app: registering the same ID twice fails. Without discovery ([manual composition](/docs/concepts/manual-composition)) `id` is required.

### `replaces`

An app action can take over a plugin action. It keeps the plugin's ID, so every button and caller keeps working:

```ts
// src/actions/add-task.ts
import { defineAction } from '@bitakit/core';

export default defineAction<string>({
  replaces: 'todos.add',
  // The app is not the todos plugin, so it declares the plugin's service.
  requires: ['todos.todos'],
  execute: ({ app, input }) => app.services.todos.add(input.trim()),
});
```

When omitted, title, description, icon, groups and order are inherited from the replaced action. `execute` and guards are not: the replacement supplies its own. Only the app can replace, and only plugin actions. See [overrides](/docs/concepts/overrides).

### `conventions` and `configPath`

`conventions: false` turns off the path-derived ID and the automatic `<id>.title` lookup; `id` and `title` are then required:

```ts
// src/plugins/todos/actions/legacy-export.ts
import { defineAction } from '@bitakit/core';

export default defineAction({
  conventions: false,
  id: 'todos.legacy-export',
  title: 'Export (legacy)',
  execute: ({ app }) => app.services.todos.list(),
});
```

`configPath` selects the config scope (`config.action`) of an action registered without discovery. By default that scope comes from the file path; without discovery it comes from the ID:

```ts
// src/manual/todos-plugin.ts
import { defineAction, definePlugin } from '@bitakit/core';

export default definePlugin({
  id: 'todos',
  config: { actions: { list: { pageSize: 10 } } },
  actions: [
    defineAction({
      id: 'todos.list',
      configPath: ['list'], // config.action reads actions.list, not actions.todos.list
      execute: ({ config }) => config.action.get('pageSize', 20),
    }),
  ],
});
```

See [type safety](/docs/concepts/type-safety) for typed IDs and inputs and [overrides](/docs/concepts/overrides) for replacing and capping actions.
