---
title: Interceptors
description: Observe or gate actions and observe service calls across a feature.
---

**Owner:** `@bitakit/core`. Interceptors attach cross-cutting behavior to existing execution and service calls. Keep feature operations in actions and services.

One helper covers both targets. A file under `interceptors/` default-exports one definition or an array of them.

## Action interceptors

```ts
// src/plugins/todos/interceptors/audit.ts
import { defineInterceptor } from '@bitakit/core';

export default defineInterceptor({
  action: 'todos.*', // exact IDs, 'todos.*' for one plugin, '*' for everything
  order: 10,
  before: ({ id, input, services }) => {
    if (id === 'todos.clear' && !services.auth.getSnapshot().user) return false; // cancels
  },
  after: ({ id, result }) => console.debug('done', id, result),
  onError: ({ id, error }) => console.error('failed', id, error),
});
```

`before` runs before `execute` and may return a promise; `false` skips the run with the reason `intercepted`. `after` and `onError` observe completed and failed runs. The context is the action's execute context plus `translate`. A definition without `action` observes every action of its own plugin.

Plugin interceptors match only their own plugin's actions unless `scope: 'global'`. App interceptors (under `src/interceptors`) are global unless `scope: 'plugin'`. `order` sorts ascending, with registration order for ties. Without `interceptors.enabled` in `bitakit.config.ts`, every discovered app interceptor is active; a list selects them.

## Service interceptors

```ts
// src/plugins/todos/interceptors/service-calls.ts
import { defineInterceptor } from '@bitakit/core';

export default defineInterceptor({
  service: 'todos.tasks',
  method: 'list',
  before: ({ args }) => console.debug('Listing tasks', args),
  after: ({ result }) => console.debug('Task count:', result.length),
  onError: ({ error }) => console.error(error),
});
```

Known service methods infer arguments and awaited results. Omitting `method` observes every public method of the service.

Service hooks observe only: return values are ignored, callbacks are not awaited and callback failures are isolated. Do not mutate arguments or results. Original sync returns, promises and errors are preserved. Internal self-calls bypass these hooks. Every consumer sees the same wrapped service; runtime disposal disables observation and disposes the original instance.

`action` and `service` are mutually exclusive in one definition; export an array to combine them in one file.
